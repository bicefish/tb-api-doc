Update Mode

This page explains the Update Mode based on a didactically reduced XML example. The focus is on delta processing, the importance of backLogDays, and the explicit treatment of deleted dealers and ads.

Particularly Relevant for Integrators, testers, and support when checking delta imports and deletion cases.
Core Point An Update Mode contains only new, changed, or explicitly deleted objects within a retrospective period.
Context

Classification

What an Update Mode Means

The export is to be understood as a change set. Objects not contained remain unchanged in the target system unless they are explicitly marked as removed via deletion containers.

Role of backLogDays

The field defines the retrospective period for which changes and deletions can reappear in the file. This creates a buffer for delayed or disrupted import processes.

Relationship to Reference Documentation

The normative description of root logic and deletion processing occurs on the pages for exchange and deletion logic. This example page shows their application.

Didactically Reduced Update Mode Example

<exchange>
  <senderName>provider-a</senderName>
  <exportDate>2024-05-15T06:00:00</exportDate>
  <transferMode>update</transferMode>
  <backLogDays>3</backLogDays>

  <dealersDeleted>
    <deleteInfo guid="dealer-99" id="99" />
  </dealersDeleted>

  <adsDeleted>
    <deleteInfo guid="ad-4711" id="4711" />
  </adsDeleted>

  <dealers>
    <dealer guid="dealer-1001" id="1001">
      <info>
        ...
      </info>
      <created>2024-01-01T09:00:00</created>
      <modified>2024-05-15T05:30:00</modified>

      <contacts>
        <contact id="12">
          <first_name>Max</first_name>
          <last_name>Mustermann</last_name>
          <email>max.mustermann@example.invalid</email>
          <languages_iso_639_1>en</languages_iso_639_1>
        </contact>
      </contacts>

      <ads>
        <ad guid="ad-5001" id="5001" category_id="210" category_name="Combine Harvester">
          <info>
            ...
          </info>
          <contact_ids>
            <contact_id>12</contact_id>
          </contact_ids>
          <price currency="EUR" taxtype="inclusive" tax_percentage="0.190">229000</price>
          <created>2024-01-10T10:00:00</created>
          <modified>2024-05-15T05:45:00</modified>
          <images>
            ...
          </images>
        </ad>
      </ads>
    </dealer>
  </dealers>
</exchange>
Area Interpretation Meaning for Target System
transferMode=update The file is to be understood as a delta delivery. Objects not contained must not be automatically deleted.
backLogDays=3 Changes and deletions from the retrospective period are redelivered. Import processes can bridge short-term failures or delays more robustly.
dealersDeleted A dealer was deleted in the retrospective period. The referenced dealer is to be treated as removed or inactive.
adsDeleted An ad was deleted in the retrospective period. The referenced ad is to be specifically removed or deactivated.
modified Shows that the delivered dealer or ad object was changed. Can be used to decide whether an existing data record needs to be overwritten.
Logic

Processing in Target System

Rule 1: Interpret File as Change Set

After evaluating transferMode=update, the target system must process only the actually contained new, changed, or deleted objects.

Rule 2: Apply Deletion Containers Explicitly

Dealers and ads appearing in dealersDeleted or adsDeleted must be specifically removed or deactivated.

Rule 3: Leave Missing Objects Unchanged

Objects that do not occur in the update and were not explicitly deleted remain in the target system.

Rule 4: Use modified for Update Decisions

For existing dealer or ad objects, the target system should check whether the delivered data records are actually more current.

Delta

Explicit Deletions

Deleted Ad

<adsDeleted>
  <deleteInfo guid="ad-4711" id="4711" />
</adsDeleted>

This entry signals an explicit deletion. The target system must not wait for the ad to be missing in a later Full file, but must apply the deletion notice directly.

Deleted Dealer

<dealersDeleted>
  <deleteInfo guid="dealer-99" id="99" />
</dealersDeleted>

This entry signals that the dealer was removed in the retrospective period. Depending on the target system, this can also have consequential effects for the associated ads.

Best Practices

Notes and Pitfalls

Typical Error: Treating Update like Full

If objects not contained are deleted although only a change set was delivered, data loss and incorrect synchronization states occur.

Typical Error: Ignoring backLogDays

Without considering the retrospective period, the robustness of the interface is underestimated and error patterns in delayed imports become difficult to trace.

Note on Didactics

The example shown here is deliberately reduced and supplements the existing example XMLs with explicit deletion cases that are not visible with the same didactic clarity in the original example file.
