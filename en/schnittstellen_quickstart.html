Getting Started

Getting Started with technikboerse Interfaces

This guide walks you through the first steps of your integration. Whether you choose the classic path via XML data exchange or prefer using the modern REST API: You will find the appropriate orientation for your scenario here.

Orientation

Choose your integration scenario

Our interfaces can be operated in different directions and technologies. To get started, choose the scenario that matches your goal. This overview serves as a guide; detailed behavior can be found on the linked reference pages.

I want to send data to technikboerse

Partner → technikboerse

Choose this path if your system provides listings or master data to technikboerse.

  • Choose between XML or REST integration
  • Review onboarding and setup requirements
  • Request credentials and technical artifacts (schema/examples)
  • Validate data flow during the test phase
  • Coordinate production date and start live operation

I want to receive data from technikboerse

technikboerse → Partner

Choose this path if technikboerse provides data that your system retrieves for further processing.

  • Choose between XML or REST integration
  • Align on delivery model and scheduling
  • Understand XML structure and mandatory elements
  • Implement processing for full sync and updates
  • Consider deletion logic, timestamps, and media handling
  • Validate data processing before production start

Perspective and Terminology ("Import" / "Export")

The terms "Import" and "Export" depend on the perspective.

  • Partner → technikboerse: Sending data to technikboerse (from the partner's perspective an "export", from our perspective an "import").
  • technikboerse → Partner: Receiving data from technikboerse (from the partner's perspective an "import", from our perspective an "export").

To avoid misunderstandings, this documentation usually uses explicit direction indicators. The structure of the XML exchange file remains identical, only transport and scheduling differ.

Workflow

Typical Onboarding Process

1

Initial Contact & Clarification

In the initial meeting, we clarify your integration goals and name the technical contacts on both sides.

2

Interface Decision

Choosing the right technology based on your requirements:

  • XML: Proven, file-based format for batch transfers.
  • REST-API: Modern, request-based integration for real-time interactions.
3

Test & Integration Phase

REST-API

  • Receipt of sandbox credentials
  • API Key & Token generation
  • Connection of test dealers
  • Validation of endpoints

XML Interface

  • Download schema & examples
  • Agreement on transport path
  • Provision of credentials
  • First test import/retrieval
4

Production Activation

After successful validation, the switch to the live environment takes place:

  • Coordination of import intervals
  • Final go-live date
  • Initial monitoring by technikboerse
Checklist

Preparation & Prerequisites

General Information

  • Business purpose & use case
  • Technical contact person
  • Desired interface (XML/REST)
  • Data direction (Import/Export)
  • Expected update frequency

Mapping: Master lists for categories and brands will be provided during onboarding. It is recommended to update these regularly via the API endpoints /adcategories and /manufacturers.

REST-Specific

  • Sandbox access requested
  • Auth scopes defined
  • Test account identifiers
  • Rollout schedule

XML-Specific

  • Transport method (FTP/HTTP)
  • Server details & credentials
  • Filename convention
  • Deletion logic strategy
  • Image provision clarified

Import-Specific

  • Dealer GUIDs known
  • Machine IDs (unique)
  • Full vs. Update mode
  • Scope (images, contacts)
