Interface Overview

REST API

This page functionally classifies the technikboerse REST API and distinguishes it from the XML interface. It serves as an overview page for integrators and project managers. The detailed technical API reference should be maintained separately and linked from here.

Page Goal Understandably present the purpose, area of application, and distinction of the REST API.
Particularly Relevant for Integrators, project managers, product management, and support.
Core Point The REST API is an independent access path and should not be mixed with the XML file interface.

Classification

Role of the REST API

The REST API supplements the file-based XML interface with API-based access. It is particularly suitable for structured queries, integration aids, and technical supplementary functions.

Documentation Principle

This page does not describe every single endpoint. It serves as an entry point and refers to the actual technical API reference.

Status in Previous Documentation

In the historical interface document, the REST API is only briefly referenced. In the HTML documentation, it should therefore be made visible and understandable as its own documentation branch.

Typical Use Cases

Retrieve Category and Attribute Information

The API is suitable for dynamically obtaining structuring reference data such as categories, manufacturers, attributes, or similar auxiliary information.

Integration-supporting Lookup Functions

If external systems should not hold complete reference data locally, the API can serve as a source for targeted lookup operations.

Supplementary System Integration

The REST API is useful when specific technical information is required without using the entire XML data exchange.

Validation and Mapping Support

API endpoints can help correctly assign categories, responsibilities, or other normative values before or during an import.

Distinction from XML Interface

Aspect REST API XML Interface
Basic Principle API-based access to structured information File-based exchange of complete or delta-based inventories
Typical Use Lookup, reference data, supplementary integration functions Regular inventory import or export
Data Scope Specific or endpoint-specific Full inventory or defined change set
Processing Model Request/Response File transfer and downstream processing
Deletion Logic To be clarified endpoint-specifically Explicitly or implicitly regulated via Full/Update

Important

The REST API should not appear in the documentation as an alternative way of writing the same XML interface. Both access paths have different integration models, expectations, and error patterns.

Notes and Pitfalls

Typical Error: Mixing REST API and XML

Integration projects lose clarity if XML inventory logic and API lookups are documented or implemented without clear separation.

Typical Error: Confusing API Overview with Technical Reference

This page is deliberately an overview page. Technical details such as parameters, return objects, or error codes belong in the API reference.

Open Point

The concrete functional use of individual API endpoints should be checked against the current product and operational status and maintained in the technical API documentation.
